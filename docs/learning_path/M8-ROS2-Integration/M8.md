# Module 8 — ROS 2 & MAVROS Integration with Project AirSim, PX4 SITL, and QGroundControl

## 1. Architecture Overview

Project AirSim supports two complementary ROS 2 integration paths when flying a PX4-controlled drone in the Unreal Engine 5 **Blocks** environment:

1. **MAVROS (`ros2` branch from [`Bmoradi93/mavros`](https://github.com/Bmoradi93/mavros))**:
   Connects to **PX4 SITL** over MAVLink UDP. Exposes PX4's flight control stack to ROS 2 (`/state`, `/local_position/pose`, `/global_position/global`, `/cmd/arming`, `/set_mode`, `/mission/push`, `/setpoint_position/local`, `/setpoint_velocity/cmd_vel`, etc.) for autonomous offboard control and waypoint missions.
2. **Project AirSim ROS 2 Bridge (`projectairsim_ros2_cpp` / `projectairsim_ros2`)**:
   Connects directly to the **Project AirSim server** on TCP ports `8989` (topics) and `8990` (services) to publish simulated perception sensors (`sensor_msgs/msg/Image`, `sensor_msgs/msg/CameraInfo`, `sensor_msgs/msg/PointCloud2`, `/tf`, `/clock`) that do not pass through PX4's MAVLink link.

### End-to-End Multi-Container Topology

All three containers run with `network_mode: host` (defined in `docker-compose.yml`), sharing `127.0.0.1` with the host OS where **QGroundControl** runs:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        Host Machine (Ubuntu + X11/GPU)                       │
│                                                                              │
│  ┌────────────────────────────────────┐   ┌───────────────────────────────┐  │
│  │ Container 1: projectairsim-dev     │   │ Host App: QGroundControl      │  │
│  │  - Unreal Engine 5.2 (Blocks)      │   │  - Listens on UDP 14550       │  │
│  │  - Project AirSim SimLibs          │   │  - Mission planning & HUD     │  │
│  │  - Python / Pixi scene loader      │   └──────────────▲────────────────┘  │
│  │    (ports 8989 / 8990)             │                  │                   │
│  └─────────┬────────────────┬─────────┘                  │ MAVLink GCS       │
│            │ TCP 4560       │ UDP 14540 ↔ 14580          │ UDP 18570 → 14550 │
│            │ (Lockstep Sim) │ (PX4 API / Offboard)       │                   │
│            ▼                ▼                            │                   │
│  ┌───────────────────────────────────────────────────────┴────────────────┐  │
│  │ Container 2: projectairsim-px4-sitl (Dockerfile.px4)                   │  │
│  │  - Ubuntu 20.04 + PX4 Autopilot v1.12.3 (make px4_sitl none_iris)      │  │
│  └───────────────────────────────────────┬────────────────────────────────┘  │
│                                          │                                   │
│                                          │ MAVLink UDP                       │
│                                          │ (14550 or dedicated 14541↔14581)  │
│                                          ▼                                   │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ Container 3: projectairsim-ros2-mavros (Dockerfile.ros2)               │  │
│  │  - ROS 2 Humble + GeographicLib datasets                               │  │
│  │  - MAVROS v2 (built from https://github.com/Bmoradi93/mavros)          │  │
│  │  - Project AirSim ROS 2 C++/Python bridge packages                     │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### Network Port Map

| Port | Protocol | Source $\leftrightarrow$ Destination | Purpose |
| :--- | :--- | :--- | :--- |
| **`8989`** | TCP (NNG Pair0) | Project AirSim Server $\leftrightarrow$ Client / ROS 2 Bridge | Pub/Sub sensor & clock topics |
| **`8990`** | TCP (NNG Req0) | Project AirSim Server $\leftrightarrow$ Client / ROS 2 Bridge | RPC services (`LoadScene`, `Arm`, etc.) |
| **`4560`** | TCP | Project AirSim (`px4-api`) $\leftrightarrow$ PX4 SITL | Lockstep physics, IMU/GPS/Baro/Mag & actuator PWM |
| **`14540` $\leftrightarrow$ `14580`** | UDP | Project AirSim (`mavlinkcom`) $\leftrightarrow$ PX4 SITL | Internal Project AirSim offboard/API control channel |
| **`14550` $\leftrightarrow$ `18570`** | UDP | QGroundControl or MAVROS $\leftrightarrow$ PX4 SITL | Default GCS MAVLink telemetry & mission channel |
| **`14541` $\leftrightarrow$ `14581`** | UDP | MAVROS $\leftrightarrow$ PX4 SITL *(optional extra stream)* | Dedicated onboard MAVLink link when QGC already uses `14550` |

## 2. Container Setup & Building

Three Dockerfiles at the repository root define the environment:

| File | Service Name | Image Name | Description |
| :--- | :--- | :--- | :--- |
| `Dockerfile` | `projectairsim-dev` | `projectairsim-dev` | Ubuntu 22.04 + Vulkan/NVIDIA + Pixi for building & running SimLibs and Unreal Engine 5.2 **Blocks**. |
| `Dockerfile.px4` | `px4-sitl` | `projectairsim-px4-sitl` | Ubuntu 20.04 + PX4 v1.12.3 SITL toolchain (`empy==3.3.4`, `pymavlink`, `nunavut`, `cmake`, `ninja`). |
| `Dockerfile.ros2` | `ros2-mavros` | `projectairsim-ros2-mavros` | `ros:humble-ros-base` + GeographicLib datasets + `Bmoradi93/mavros` (`ros2` branch) prebuilt in `/opt/mavros_ws`. |

### Step 1: Configure `.env`

Ensure `.env` at the repository root points to your Unreal Engine 5.2 checkout and your cloned `PX4-Autopilot` repository:

```dotenv
UE_ROOT_HOST_PATH=/home/behnam/git/UnrealEngine-5.2.0-release
PX4_HOST_PATH=/home/behnam/git/ProjectAirSim/PX4-Autopilot
VIDEO_GID=44
RENDER_GID=991
INPUT_GID=994
```

### Step 2: Prepare `PX4-Autopilot` on `v1.12.3`

Project AirSim requires **PX4 v1.12.3**. Make sure the `PX4-Autopilot` checkout is on tag `v1.12.3` with submodules initialized:

```bash
cd /home/behnam/git/ProjectAirSim/PX4-Autopilot
git checkout v1.12.3
git submodule sync --recursive
git submodule update --init --recursive
```

### Step 3: Build All Three Docker Images

From `/home/behnam/git/ProjectAirSim`:

```bash
docker compose build projectairsim-dev
docker compose build px4-sitl
docker compose build ros2-mavros
```

And compile the PX4 SITL binary once inside `px4-sitl` (build artifacts persist on the host in `PX4-Autopilot/build/px4_sitl_default/`):

```bash
docker compose run --rm px4-sitl make px4_sitl_default
```

## 3. Step-by-Step: Launching the Full Simulation Stack

> **Critical Rule for PX4 SITL**: Whenever you stop a flight session or reload a scene in Project AirSim, you **must restart PX4 SITL** (`docker restart projectairsim-px4-sitl` or `Ctrl+C` and re-run) before loading the next scene. A PX4 SITL instance only accepts a TCP connection on port `4560` once per startup.

### Terminal 1 — Launch `projectairsim-dev` & Unreal Engine Blocks

1. On the host, grant X11 access to Docker once per login session:
   ```bash
   xhost +local:docker
   ```
2. Start the `projectairsim-dev` container:
   ```bash
   docker compose run --rm projectairsim-dev
   ```
3. Inside the container, launch the Unreal Engine **Blocks** Editor (or use `-game` mode) via the root `Makefile`:
   ```bash
   make editor
   # Equivalent to:
   # $UE_ROOT/Engine/Binaries/Linux/UnrealEditor /workspace/ProjectAirSim/unreal/Blocks/Blocks.uproject
   ```
   *(Or run `make game` to launch directly into Game mode without the Editor UI.)*
4. Once the Unreal Editor window opens, click the green **Play** button in the top toolbar.
   - Blocks is now running and listening on ports `8989` and `8990`.

### Terminal 2 — Launch PX4 SITL (`px4-sitl`)

From the host in `/home/behnam/git/ProjectAirSim`:

```bash
docker compose run --rm px4-sitl
```

You will see PX4 initialize and pause waiting for Project AirSim to connect on TCP port `4560`:

```text
______  __   __    ___ 
| ___ \ \ \ / /   /   |
| |_/ /  \ V /   / /| |
|  __/   /   \  / /_| |
| |     / /^\ \ \___  |
\_|     \/   \/     |_/

px4 starting.

INFO  [px4] Calling startup script: /bin/sh etc/init.d-posix/rcS 0
...
PX4 SIM HOST: localhost
INFO  [simulator] Waiting for simulator to accept connection on TCP port 4560
```

> **Note**: While PX4 is waiting at `Waiting for simulator to accept connection on TCP port 4560`, it has **not** started its MAVLink UDP streams yet. QGroundControl and MAVROS will connect as soon as the drone is spawned in Terminal 3.

### Terminal 3 — Spawn the PX4 Drone in Blocks

Open a shell inside the running `projectairsim-dev` container:

```bash
docker exec -it projectairsim-dev bash
cd /workspace/ProjectAirSim/client/python/example_user_scripts
pixi run python px4_mission.py sitl
```

What happens when you run this command:
1. It loads `sim_config/scene_px4_sitl.jsonc` and `sim_config/robot_quadrotor_px4_sitl.jsonc` into Unreal Blocks.
2. It opens the three OpenCV camera windows (`ChaseCam`, `RGB-Image`, `Depth-Image`).
   - *Note*: Ensure `"capture-enabled": true` is set under the `"Chase"` camera in `sim_config/robot_quadrotor_px4_sitl.jsonc` so the `sensors["Chase"]["scene_camera"]` topic is published.
3. Project AirSim connects to PX4 SITL on TCP port `4560`.
4. The script pauses at:
   ```text
   Ready to begin mission.  Wait for PX4 to commence GPS fusion and press enter.
   ```
   **Leave it at this prompt (do NOT press Enter)** if you want to control the drone via **MAVROS** or **QGroundControl**! Leaving it paused keeps the scene and camera streams alive without the Python script taking over API control.

Look at **Terminal 2 (PX4 SITL)** and wait ~5 seconds until you see EKF alignment and GPS fusion complete:

```text
INFO  [simulator] Simulator connected on TCP port 4560.
INFO  [mavlink] mode: Normal, data rate: 4000000 B/s on udp port 18570 remote port 14550
INFO  [mavlink] mode: Onboard, data rate: 4000000 B/s on udp port 14580 remote port 14540
INFO  [ecl/EKF] GPS checks passed
INFO  [ecl/EKF] 4107000: EKF aligned, (baro hgt, IMU buf: 12, OBS buf: 9)
INFO  [ecl/EKF] starting GPS fusion
INFO  [tone_alarm] home set
```

## 4. Connecting QGroundControl (Optional)

If you want to run **QGroundControl** on the host machine:

1. Launch the AppImage (pass `--appimage-extract-and-run` if `libfuse2` is not installed on Ubuntu 22.04/24.04):
   ```bash
   ./QGroundControl-x86_64.AppImage --appimage-extract-and-run
   ```
2. In **Application Settings $\rightarrow$ Comm Links**, configure a UDP link (or use the default UDP link):
   - **Type**: `UDP`
   - **Port**: `14550`
   - **Server Addresses**: `127.0.0.1:18570`
   - **High Latency**: **OFF** *(must be unchecked so real-time telemetry is not suppressed)*

## 5. Launching MAVROS in ROS 2 (`ros2-mavros`)

### Terminal 4 — Start the `ros2-mavros` Container

From `/home/behnam/git/ProjectAirSim`:

```bash
docker compose run --rm ros2-mavros
```

Inside this container, `/opt/ros/humble/setup.bash` and `/opt/mavros_ws/install/setup.bash` are automatically sourced. Verify the MAVROS packages are available:

```bash
ros2 pkg list | grep mavros
# Output:
# mavros
# mavros_examples
# mavros_extras
# mavros_msgs
```

### Choose How MAVROS Connects to PX4

#### Case A: MAVROS Only (QGroundControl Closed)
Connect MAVROS directly to PX4's default GCS UDP link (`14550` $\leftrightarrow$ `18570`):

```bash
ros2 launch mavros px4.launch fcu_url:="udp://:14550@127.0.0.1:18570"
```

#### Case B: MAVROS + QGroundControl Running Simultaneously
If QGroundControl is also open, you can either:
1. **Use MAVROS's built-in `gcs_url` proxy** (MAVROS binds to `14550` and forwards MAVLink to QGroundControl on port `14551`):
   ```bash
   ros2 launch mavros px4.launch \
     fcu_url:="udp://:14550@127.0.0.1:18570" \
     gcs_url:="udp://@127.0.0.1:14551"
   ```
2. **Or start a second dedicated onboard MAVLink stream in PX4 (`pxh>` console in Terminal 2)**:
   ```text
   mavlink start -x -u 14581 -r 4000000 -f -m onboard -o 14541
   ```
   And connect MAVROS to `14541`:
   ```bash
   ros2 launch mavros px4.launch fcu_url:="udp://:14541@127.0.0.1:14581"
   ```

## 6. Testing & Controlling the Drone via ROS 2 (MAVROS)

Open a second shell inside the running `projectairsim-ros2-mavros` container:

```bash
docker exec -it projectairsim-ros2-mavros bash
```

*(Note: Depending on how `px4.launch` namespaces the node in your version of `Bmoradi93/mavros`, topics are published either at the root namespace `/state`, `/local_position/pose`, `/cmd/arming` or under `/mavros/...`. Check with `ros2 topic list`.)*

### 1. Verify Connection & FCU State

```bash
ros2 topic echo /state --once
```

Expected output:

```yaml
header:
  stamp:
    sec: 1793567023
    nanosec: 452038169
  frame_id: ''
connected: true
armed: false
guided: true
manual_input: false
mode: AUTO.LOITER
system_status: 3
```

- `connected: true`: MAVROS is receiving MAVLink heartbeats from PX4 SITL.
- `guided: true`: PX4 is ready to accept external commands.
- `system_status: 3` (`MAV_STATE_STANDBY`): EKF/GPS preflight checks have passed and the vehicle is ready to arm.

### 2. Inspect Telemetry Topics from Blocks + PX4

```bash
# Local ENU position estimated by PX4 EKF2 from Project AirSim sensors
ros2 topic echo /local_position/pose --once

# Global GPS coordinates (matches home-geo-point 47.641468, -122.140165 in scene_px4_sitl.jsonc)
ros2 topic echo /global_position/global --once

# Simulated IMU data flowing through PX4
ros2 topic echo /imu/data --once
```

### 3. Arm, Takeoff, and Land via ROS 2 Services

```bash
# 1. Switch to AUTO.TAKEOFF mode
ros2 service call /set_mode mavros_msgs/srv/SetMode "{custom_mode: 'AUTO.TAKEOFF'}"

# 2. Arm the drone (it will spin propellers in Blocks and climb to takeoff altitude)
ros2 service call /cmd/arming mavros_msgs/srv/CommandBool "{value: true}"

# 3. Land the drone back in Blocks
ros2 service call /set_mode mavros_msgs/srv/SetMode "{custom_mode: 'AUTO.LAND'}"
```

### 4. Offboard Control (`OFFBOARD` Mode)

PX4 requires a continuous stream of setpoints at **$\ge 2\text{ Hz}$** *before* it will allow switching into `OFFBOARD` mode:

1. **Stream position setpoints (e.g., hover at $z = 5\text{ m}$ ENU / Up)** in one terminal:
   ```bash
   ros2 topic pub -r 20 /setpoint_position/local geometry_msgs/msg/PoseStamped \
     "{header: {frame_id: 'map'}, pose: {position: {x: 0.0, y: 0.0, z: 5.0}, orientation: {w: 1.0}}}"
   ```
   *(Or stream velocity setpoints to `/setpoint_velocity/cmd_vel_unstamped`.)*

2. **Switch to `OFFBOARD` mode and arm** in another terminal:
   ```bash
   ros2 service call /set_mode mavros_msgs/srv/SetMode "{custom_mode: 'OFFBOARD'}"
   ros2 service call /cmd/arming mavros_msgs/srv/CommandBool "{value: true}"
   ```
   Watch the drone in the Unreal **Blocks** window climb to $(0, 0, 5)$ and track any changes you publish to `/setpoint_position/local`!

### 5. Executing Waypoint Missions (`AUTO.MISSION`)

You can upload a mission either from **QGroundControl** (Plan View $\rightarrow$ Upload) or programmatically via MAVROS's `/mission/push` service (`mavros_msgs/srv/WaypointPush`), and then trigger mission execution from ROS 2:

```bash
# Verify waypoints are loaded on PX4
ros2 topic echo /mission/waypoints --once

# Arm and start the mission
ros2 service call /cmd/arming mavros_msgs/srv/CommandBool "{value: true}"
ros2 service call /set_mode mavros_msgs/srv/SetMode "{custom_mode: 'AUTO.MISSION'}"
```

## 7. Bridging Project AirSim Cameras & LiDAR into ROS 2 (`projectairsim_ros2_cpp`)

While MAVROS bridges PX4's flight controller state and commands, high-bandwidth Unreal Engine sensors (RGB cameras, depth cameras, segmentation, LiDAR, radar) are bridged directly from Project AirSim using `projectairsim_ros2_cpp`.

Inside the `ros2-mavros` container (after building the C++ client library):

```bash
# 1. Build the ROS 2 C++ bridge package
cd /workspace/ProjectAirSim/ros
colcon build --packages-select projectairsim_ros2_cpp
source install/setup.bash

# 2. Run the bridge (attach to the already-loaded scene or load scene_px4_sitl.jsonc directly)
ros2 run projectairsim_ros2_cpp projectairsim_ros2_cpp_node --ros-args \
  -p scene_config:=scene_px4_sitl.jsonc \
  -p sim_config_path:=/workspace/ProjectAirSim/client/python/example_user_scripts/sim_config
```

*(Note: When `projectairsim_ros2_cpp_node` loads `scene_px4_sitl.jsonc` directly, you do not need to run `px4_mission.py` at all—the ROS 2 C++ node spawns the drone in Blocks, publishes `/clock`, `/tf`, and all camera/LiDAR topics under `/ProjectAirsim/...`, while MAVROS simultaneously controls PX4!)*

## 8. Troubleshooting Reference

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| `ModuleNotFoundError: No module named 'projectairsim'` | Running global `/usr/bin/python3` instead of the Pixi environment. | Prefix Python commands with `pixi run` (e.g., `pixi run python px4_quadrotor.py sitl`). |
| `UnrealEditor-Linux-DebugGame` exits with `Incompatible or missing module: Blocks` | The latest build in `unreal/Blocks/Binaries/Linux/` was built with `blocks_development` instead of `blocks_debuggame`. | Run `make editor` (which invokes `$UE_ROOT/Engine/Binaries/Linux/UnrealEditor`), or rebuild `blocks_debuggame`. |
| `KeyError: 'scene_camera'` on `drone.sensors["Chase"]["scene_camera"]` | `"capture-enabled"` was set to `false` on the `"Chase"` camera in `robot_quadrotor_px4_sitl.jsonc`. | Ensure `"capture-enabled": true` under the `"Chase"` sensor in `sim_config/robot_quadrotor_px4_sitl.jsonc`. |
| `RuntimeError: ERROR code: 2.0, message: std::exception` on `drone.enable_api_control()` | PX4 SITL was not restarted after a previous flight session or scene reload. | Run `docker restart projectairsim-px4-sitl` before loading the scene again. |
| `./QGroundControl-x86_64.AppImage` fails with `Cannot mount AppImage, please check your FUSE setup` | `libfuse2` is missing on the host or inside Docker. | Run `./QGroundControl-x86_64.AppImage --appimage-extract-and-run`. |
| QGroundControl or MAVROS stays `Disconnected` even though PX4 and Blocks are running | No scene has been loaded into Blocks yet, so PX4 is still paused waiting on TCP port `4560`. | Load `scene_px4_sitl.jsonc` (via `pixi run python px4_mission.py sitl` or `projectairsim_ros2_cpp_node`). |
